# 成员1补充材料对应与运行状态

依据：2026年10月29日组长《成员1数据采集材料补充说明》，以及课程《中期大作业》第七、第八部分。老师要求代表性样本和README复现步骤；建议文件名、机场、日期、样本大小与单独抽样说明均非老师指定格式。

| 补充事项 | 本包提供什么 | 何时算完成 |
|---|---|---|
| 代表性原始样本 | 确定性范围导出脚本，原值保留、机场站点映射、保守UTC窗口、来源哈希和自动条数 | 采集者在现有原项目实际运行成功，生成data/samples/raw/member1及导出回执 |
| 抽样解释 | 预先给出固定选取规则，运行后自动生成真实范围及条数的README和manifest | 不把预期条数或测试数据写成真实结果；缺少类别时如实记录 |
| 采集模块运行步骤 | README_member1.md，包含环境、目录、公开地址、真实依赖顺序、弹窗目录、输出及异常判定 | 组长可并入全组README；保持真实历史与当前脚本版本区分 |
| BTS体积常量改进（建议项） | 新增动态读取BTS manifest并核对本地文件大小的audit_source_sizes.py；给出旧脚本可用替换语句 | 本机生成source_size_audit.json；无需覆盖旧脚本即可将动态报告用于最终统计 |

不改变成员分工：样本导出不构建一行一航班的天气融合表，不做天气值清洗、时区逐班匹配、州界空间Join或模型。缺失、时区和天气质量仍由后续成员处理。所选样本窗口足够宽不等于90分钟逐班匹配率已验证。

本包发布时仅具备文档和脚本，不包含真实样本，也不附测试夹具冒充原始数据。发布前验证包括：Python语法、隔离夹具端到端导出、原值／列顺序保留、UTC窗口边界、文件哈希、原始文件不变、重复运行防覆盖，以及BTS manifest汇总不一致时停止。具体脚本验证见同目录SOFTWARE_VALIDATION.md。
